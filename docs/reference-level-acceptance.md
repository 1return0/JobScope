# JobScope参考级验收门槛

## 目的

本门槛用于保证JobScope最终不是“上传文件后聊天”的演示，而是具备数据规模、检索实验、结构化查询、可靠性和性能证据的完整RAG项目。

参考简历只用于比较项目成熟度，不复制其业务数据、代码或未经复现的指标。

## A. 数据与解析

- [ ] 至少120条真实公开岗位快照，覆盖至少8家企业；
- [ ] 每条记录包含来源URL、来源类型、发布时间、抓取时间、最终URL和内容哈希；
- [ ] HTML、PDF、扫描PDF、DOCX、XLSX、PPTX均有解析回归样本；
- [ ] 形成约1000个带稳定Evidence ID的片段；
- [ ] 形成400条以上结构化岗位要求；
- [ ] 页码、标题路径、Sheet/单元格和幻灯片编号可以回溯；
- [ ] 公开仓库不保存他人简历或需要登录才能取得的数据。

## B. 检索与结构化查询

- [ ] BM25基线；
- [ ] Dense基线；
- [ ] BM25+Dense+RRF；
- [ ] Hybrid+Cross-Encoder Reranker；
- [ ] 公司、岗位、城市、学历、届别、招聘类型和发布时间过滤；
- [ ] 必须项、加分项与职责分类；
- [ ] 公司、岗位和版本隔离；
- [ ] 信息不足时拒答；
- [ ] 招聘文档Prompt Injection测试。

## C. 黄金集和实验

- [ ] 至少80条人工核验问题；
- [ ] 包含事实、比较、过滤、版本、冲突、跨公司污染和拒答题；
- [ ] 报告Recall@1、Recall@5、MRR、nDCG和引用准确率；
- [ ] 四组检索实验使用同一Corpus Snapshot和同一问题集；
- [ ] 至少10个Bad Case有错误分类、原因和修复记录；
- [ ] 不仅报告最好结果，也保留失败实验。

## D. 工程与性能

- [ ] FastAPI接口和JSON Schema；
- [ ] 向量库与结构化数据库；
- [ ] 缓存、限流、超时、重试、降级和熔断；
- [ ] 日志、Trace ID和关键指标；
- [ ] 固定60请求、并发24的压测配置；
- [ ] 报告吞吐、P50、P95、错误率和资源占用；
- [ ] 优化前后使用相同数据和请求配置；
- [ ] 自动化测试覆盖解析、检索、过滤、引用和接口契约。

## E. 面试交付

- [ ] 3分钟业务介绍；
- [ ] 10分钟架构与实验介绍；
- [ ] 可独立运行的演示；
- [ ] 架构图和数据流图；
- [ ] 评测报告、压测报告和Bad Case报告；
- [ ] 能解释为什么使用RRF和Reranker；
- [ ] 能解释为什么固定Workflow比伪Multi-Agent更适合检索链路；
- [ ] 简历中的每个数字都能由脚本和报告复现。

## 与参考项目的差异化

JobScope不依赖把检索链路包装成多个Agent来增加复杂度。它以确定性摄取和检索流水线为主，将Multi-Agent能力留给ServiceFlow。差异化重点是：

- 招聘页面版本和内容哈希；
- 多格式来源与证据坐标；
- 当前岗位和过期岗位隔离；
- 必须项、加分项和职责的可解释抽取；
- 引用、拒答、Prompt Injection和可复现实验。
