## 冻结开发顺序

1. JobScope 查询正确性：显式岗位编号、保留城市/岗位约束、招聘 FAQ 路由、不能执行的硬筛选明确拒绝。
2. 两项目接入可选 pgvector Dense 后端：查询确实由 PostgreSQL vector 距离执行；原后端保留用于回归。校验模型身份、维度与 corpus fingerprint，原子发布完整快照，不静默读旧库或降级。
3. 以 JobScope 为文档办公演示：已检索证据生成可编辑岗位对比报告、结构化修改预览、显式确认、导出 Word，保持引用与版本边界；ServiceFlow 只做公共知识答复的对应导出，不把原工单正文/JWT 暴露到文件或工具。
4. 执行隔离只服务受控文档导出：非任意 Shell；固定 worker、独立文件边界、超时/大小限制。未真实验证容器/OS 强隔离前不得宣称「执行沙箱已完成」。
5. 端到端验收及前端补齐；逐项区分单测、真实 PostgreSQL、真实模型、浏览器、隔离环境。外部环境未跑不是 passed。

不新增自由 Agent 辩论、任意代码执行、训练、分布式 Worker；不为岗位关键词堆功能。
